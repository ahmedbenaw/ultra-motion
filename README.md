# ULTRA Motion — development preview

Portable product and decision studio for product managers, designers, builders, business analysts, consultants, founders, executives, investors and academic researchers.

The 0.4.0 source package is available in this repository as **ULTRA-Motion-0.4.0-development.zip**. It contains one `reelcraft/` directory with both host manifests, eight workflow skills, local MCP tools, hooks, templates, scripts and evals. Extract it before using its local entry points. The repository currently publishes the source archive; a normal unpacked source tree and GitHub CI publication are pending integration write permission for this new repository.

## Implemented and tested

- Semantic Moments, exact plan approval, revision checks and repeat-safe commands.
- Twenty-nine starting recipe families; case-specific rule-based proposals, explicit conflict composition and saved personal recipes.
- Scoped dependency work with foreground/background execution, cooperative controls and stale-result detection.
- Draft MP4, transparent MOV, PNG, WebM and GIF; captions, JSON, restricted Lottie, PDF/PPTX briefings and exact-sample PCM WAV.
- Local project branches and recovery, including Unicode filenames and edited drafts.

The package records exact constraints in `reelcraft/docs/exports.md`. These exports are bounded drafts and briefings; they do not establish final motion, expert consulting quality or native-host acceptance.

## Start with a capable coding host

Give the archive to your coding assistant and ask it to extract the package, read `README.md`, run the runtime doctor, and show a project plan before starting work. The local runtime requires Python 3.10+, Node 22+ and FFmpeg. PDF/PPTX dependencies can be installed with `python3 scripts/setup.py --exports` from the extracted directory.

Loading skills alone does not install media dependencies or make a local process available in chat on web/mobile. Native ChatGPT, Codex, Claude and Claude Code installation, live artifact interaction and voice-to-tool behavior still require target-host qualification. The current interactive loopback room is optional development tooling, not a replacement for the requested native experience.
